# Comparison Matrix Template

This is the canonical structure for comparing 2+ vendor responses. Use this template even for 2-vendor comparisons — it scales up cleanly.

## Section structure

### A. Header / context

```
מכרז:           [שם המכרז]
מספר:           [מספר רשמי]
לקוח:           [שם הלקוח]
תאריך הגשה:     [תאריך אחרון להגשה]
מספר ספקים:     [N]
תאריך ניתוח:    [תאריך כתיבת הדוח]
מנתח (Vono):    [שם היועץ]
```

### B. Executive summary table

טבלה אחת. שורה אחת לכל ספק:

```
| דירוג | ספק     | ניקוד | דגל סיכון | המלצה                        |
|-------|---------|-------|-----------|------------------------------|
| 1     | ספק א'  | 87.4  | 🟢        | להמליץ - עומד בכל הדרישות     |
| 2     | ספק ב'  | 81.2  | 🟡        | אופציה - דרושה הבהרה לסעיף 4 |
| 3     | ספק ג'  | 74.5  | 🔴        | לא מומלץ - חששות ארכיטקטורה  |
```

### C. Threshold conditions table

```
| תנאי סף                          | ספק א | ספק ב | ספק ג |
|----------------------------------|-------|-------|-------|
| אישור ניהול ספרים                |  ✓   |  ✓   |  ✓   |
| ערבות מכרז (500,000 ₪)           |  ✓   |  ✓   |  ✓   |
| ניסיון: 3+ פרויקטים בהיקף [X]    |  ✓   |  ✓*  |  ✓   |
| תעודת ISO 27001 תקפה            |  ✓   |  ✓   |  ✗   |
| צוות מפתח מוסמך                  |  ✓   |  ✓   |  ✓   |
| העדר ניגוד עניינים               |  ✓   |  ✓   |  ✓   |

* ספק ב' - 2 פרויקטים בהיקף הנדרש + 1 בהיקף 80%. דרושה החלטת ועדה.
✗ ספק ג' - תעודה פגה לפני 4 חודשים. דרוש בירור דחוף.

### D. Detailed scoring per criterion

לכל ספק, פירוט מלא:

```
ספק א' - חישוב ניקוד מפורט
==============================

מחיר (משקל 70%):
- הצעה: 4.2M ש"ח
- הצעה הנמוכה ביותר: 3.5M ש"ח
- ניקוד: (3.5M / 4.2M) × 70 = 58.3 / 70

איכות (משקל 30%):
- ניסיון מוכח (10%):                9 / 10  
  סיבה: 5 פרויקטים מתוכם 4 בתחום
- CV של אנשי המפתח (10%):           8 / 10  
  סיבה: ראש צוות 12 שנים, חברי צוות 7-9 שנים
- מתודולוגיה (5%):                  4 / 5  
  סיבה: Discovery + Build + Deploy מסודרים, חסרה phase למידה ארגונית
- הצעה טכנית / NFR (5%):            4 / 5  
  סיבה: 92% כיסוי. NFR-12 (data residency) נענה רק חלקית.

ניקוד איכות סה"כ:                  25 / 30

ניקוד סופי:                          83.3 / 100
```

### F. Strengths & weaknesses summary (per vendor)

```
ספק א' - חזקות
- ניסיון רחב בתחום (5 פרויקטים בנקאיים ב-3 השנים האחרונות)
- ראש צוות עם רקורד מוכח (12 שנים, 4 פרויקטים דומים)
- הצעה טכנית מפורטת ומגובת קונפיגורציות

ספק א' - חולשות
- מחיר גבוה ב-20% מהממוצע
- מתודולוגיה חסרה phase של ניהול שינוי ארגוני
- NFR-12 (data residency) נענה חלקית - דרושה הבהרה

ספק א' - דרישות הבהרה
1. מיקום ה-backup data center (סעיף 4.5.2)
2. תוכנית learning ושינוי ארגוני (סעיף 6.1)
3. exit clause - תקופת transition (סעיף 8.4)
```

### G. Risk analysis (cross-vendor)

```
🔴 דגלים אדומים
- ספק ג': תעודת ISO 27001 פגה. ללא בירור דחוף - פסילה.
- ספק ג': מחיר 35% מתחת לאומדן - חשד ל-underbid. דרוש בירור על המודל הכלכלי.

🟡 דגלים צהובים
- ספק ב': צוות מפתח לא נכלל בהסכם בלעדיות - דרישה להוסיף סעיף בלעדיות.
- ספק א': data residency מעורפל. דרושה הבהרה.
- שני ספקים (א' ו-ב') לא הציעו תוכנית transition מסודרת לסיום ההתקשרות.

🟢 ירוק
- ספק א' - בכפוף להבהרות, הצעה איכותית.
```

==========================

ספק מומלץ ראשון:    ספק א'
ניקוד:               83.3 / 100
דגל סיכון:           🟢 ירוק (לאחר הבהרות)

נימוק:
ספק א' מציע איכות הגבוהה ביותר במכרז עם רקורד מוכח בתחום הספציפי.
המחיר גבוה אך מוצדק במונחי הפחתת סיכון פרויקטלי. שלוש דרישות הבהרה
מהותיות - אם ייענו תוך 5 ימי עבודה, ניתן להתקדם לחתימת חוזה.

חלופה שנייה:        ספק ב'
ניקוד:              81.2 / 100
דגל סיכון:          🟡 צהוב

הערה:
ההפרש בניקוד (2.1 נקודות) נמצא בטווח הסטטיסטי המקובל. ספק ב' זול
ב-15% וצוותו עומד בדרישות, אך יש פערים בכיסוי NFR. אם ספק א'
לא יענה על דרישות ההבהרה - יש להמשיך לספק ב'.

ספק ג': לא מומלץ.
תעודת ISO לא תקפה (פסילת תנאי סף) + חששות מ-underbid.
```

## Formatting rules

- **No paraphrasing** of vendor claims. Direct quotes with page numbers.
- **No subjective language** ("הצעה איכותית", "ספק מוביל") without backing data.
- **Hebrew throughout** - אם ההצעה באנגלית, ציטוט במקור + תרגום בסוגריים.
- **Reference everything** - `(עמ' 14, סעיף 3.2.1)` אחרי כל ממצא.
- **Numerical scoring** - הצגו את החישוב, לא רק התוצאה.

## Length guidance

- Executive summary: עמוד 1
- Threshold + scoring + risk: 3-5 עמודים
- Coverage matrix (נספח): כמה שצריך, יכול להיות 20+ עמודים במכרזים גדולים
- סך הכל: דוח רגיל - 8-15 עמודים. דוח מורכב - עד 30.
