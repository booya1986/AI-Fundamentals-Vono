# RFP Section Templates

Three canonical structures, calibrated to different procurement categories. Pick one — don't mix.

## Template A — Technology / System Procurement

For software systems, infrastructure, BI tools, LMS, CRM, ERP, etc.

### 1. רקע ומטרות
- מי הלקוח (גוף ציבורי, חברה ממשלתית)
- הצורך העסקי שמניע את המכרז
- היעדים האסטרטגיים שהמערכת תשרת
- היקף תקציבי משוער (אם פתוח)

### 2. תיאור הצורך
- תיאור עסקי של הפתרון הנדרש
- היקף המשתמשים (פנים-ארגוני / קצה / ציבור הרחב)
- נפחי שימוש משוערים (טרנזקציות ליום, רשומות במאגר)
- תהליכים עסקיים נדרשים (אם רלוונטי)

### 3. דרישות פונקציונליות
- רשימה ממוספרת של פונקציות חובה (`F-001`, `F-002`, ...)
- רשימה ממוספרת של פונקציות רצויות
- כל דרישה - שורה אחת, חד-משמעית, ניתנת לבדיקה
- חלוקה לקטגוריות לפי מודולים

### 4. דרישות לא-פונקציונליות
- ביצועים (זמני תגובה, throughput)
- זמינות ו-SLA
- מדרגיות
- אבטחת מידע (ת"י 27001 לפחות, או דרישת המבטחים)
- נגישות (ת"ק 5568 — לכל ממשק משתמש)
- שפה (תמיכה בעברית מלאה: RTL, גופנים, ניקוד)
- אינטגרציות נדרשות

### 5. ארכיטקטורה ופריסה
- on-prem / cloud / hybrid
- dedicated tenant / shared / multi-tenant
- דרישות גיאוגרפיות (data residency)
- backup ו-DR

### 6. דרישות עמידה ברגולציה
- חוק הגנת הפרטיות (תיקון 13)
- תקנות אבטחת מידע
- הנחיות הרשות לחדשנות / רגולטור הענף הספציפי
- הנחיית רשם מאגרי המידע (אם רלוונטי)

### 7. תנאי סף (Threshold Conditions)
- כל תנאי - חד-משמעי, אובייקטיבי, ניתן להוכחה במסמך
- ניסיון מוכח (X שנים, Y פרויקטים דומים)
- מחזור כספי מינימלי
- צוות מוסמך (תפקיד + רמת ניסיון)
- תעודות תקנים תקפות
- העדר הליכים משפטיים מהותיים

### 8. אמות מידה לבחירה
- חלוקה ברורה: מחיר X% / איכות Y%
- פירוט הסעיפים תחת "איכות"
- שיטת ניקוד מפורטת (יחסית / מוחלטת / שיטת השוואה)

### 9. לוחות זמנים
- פרסום המכרז
- מועד אחרון לשאלות הבהרה
- מועד תשובות הוועדה
- מועד אחרון להגשה
- תקופת בחינה משוערת
- תאריך התחלה משוער

### 10. תהליך הגשה
- פורמט (PDF, מעטפה חתומה, פורטל)
- ערבות מכרז (סכום, סוג, תוקף)
- מסמכים נדרשים (רשימה ממוספרת)
- כתובת פיזית / כתובת מערכת
- חתימות נדרשות
- שפת ההגשה

### 11. תנאים מסחריים
- מבנה מחיר (חד-פעמי, חוזרת, hybrid)
- תקופת התקשרות + אופציות הארכה
- תנאי תשלום
- מנגנון הצמדה
- קנסות איחור / SLA

### 12. נספחים
- A. הצהרות חובה (אישור ניהול ספרים, ערבות, היעדר הרשעות)
- B. הצהרת שמירה על סודיות
- C. תצהיר העדר ניגוד עניינים
- D. טפסי הגשה סטנדרטיים
- E. מפרט טכני מפורט (אם נדרש)

## Template B — Professional Services / Consulting

For consulting projects, training programs, implementation services without bundled software.

### 1. רקע ומטרות
- ראו טמפלייט A.

### 2. תיאור המשימה
- תוצרים מוגדרים (deliverables) ולא תהליכים
- היקף השעות / הימים / שלבי הפרויקט
- קהל יעד של הפרויקט (אם רלוונטי - מספר משתתפים, פרופיל)

### 3. מתודולוגיה נדרשת
- שיטת עבודה כללית
- תוצרי-ביניים בכל שלב
- מנגנוני בקרה ואישור
- שיתוף פעולה עם צוות הלקוח

### 4. דרישות מהצוות המבצע
- ראש צוות (מנהל הפרויקט) - ניסיון מינימלי
- חברי צוות - תפקידים, רמות ניסיון
- כפילות מוצעת
- שפת תקשורת (עברית בלבד / עברית + אנגלית)

### 5. תנאי סף לספק
- ניסיון בפרויקטים דומים בהיקף ובתחום
- מחזור כספי
- צוות זמין
- תעודות / הסמכות

### 6. אמות מידה לבחירה
- מחיר (במשרות שירות מקצועי בדרך כלל 30-40%)
- ניסיון מוכח
- צוות מקצועי (CV של אנשי המפתח)
- מתודולוגיה מוצעת
- ראיון / מפגש עם הצוות (לעיתים)
- references

### 7-12 - כמו טמפלייט A.

## Template C — Hybrid (System + Ongoing Services)

For procurements that combine a software system with implementation, training, and multi-year SLA.

### 1-6 - כמו טמפלייט A, עם הוספה של:

### 5b. דרישות שירות (Service Requirements)
- היקף שעות implementation
- ימי הדרכה ייעודיים (משתמשים, אדמינים)
- זמינות תמיכה (24/7, 8x5, וכו')
- ימי תגובה לפי דרגות חומרה
- maintenance windows מותרים

### 6b. דרישות תפעול ארוך-טווח
- תקופת התקשרות (3, 5, 7 שנים)
- אופציות הארכה
- מנגנון פיתוח מותאם (Change Requests)
- backup ו-DR procedures
- exit plan (transition assistance למתחרה אחר בסיום)

### 7-12 - כמו טמפלייט A, עם תנאי סף נוספים:
- ניסיון בתפעול מערכות בהיקף דומה (לא רק הקמה)
- צוות תפעולי קבוע בארץ
- מערך שירות 24/7 בעברית
